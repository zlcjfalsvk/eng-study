## 입력과 출력
- 입력: 배치 파일(한 줄에 `headword,type`). 이 표제어들만, 빠짐없이, 철자·유형 그대로 작성한다.
- 출력: 지정된 경로의 **JSONL** 파일. 한 줄에 Entry 객체 하나(JSON.stringify 한 줄), 줄바꿈으로 구분. 배열로 감싸지 않는다.
- 검증: `cd /Users/cheolmin/Project/charlie/eng && pnpm validate:part <출력파일> --level <level>` 이 ✓ 로 끝나야 한다. 실패 메시지를 보고 고친 뒤 재검증한다.
- 다른 파일은 수정하지 않는다. content/ 아래 파일은 절대 직접 건드리지 않는다(병합은 별도 단계).

## 대상 학습자
한국어 화자 성인. 단어의 뜻을 "한두 개"가 아니라 **상황별로 갈리는 뜻**으로 배우고 싶어 함.
각 뜻마다 자연스러운 예문(영/한)이 있고, 예문은 브라우저 TTS 로 읽히므로 실제 말하듯 자연스러운 문장이어야 함.

## 레벨 정의
- beginner (id 접두사 b-): CEFR A1~A2. 일상·학교·가족·음식·시간·날씨. 예문 6~12단어, 구어체.
- intermediate (i-): B1~B2. 뉴스·여행·감정·의견·추상어 입문. 예문 8~14단어.
- advanced (a-): C1~C2. 학술·시사·에세이·문학. 뉘앙스·격식 중요. 예문 8~16단어, 사설/학술/문학 문체. 단순 유의어와의 차이를 note 에.
- business (z-): 회의·이메일·협상·재무·마케팅·프로젝트. 격식/비격식 구분. 예문 8~16단어, 실제 업무 문장. 고객 이메일에 부적절한 표현은 note 로 경고.

## 엔트리 규칙
1. **다의어는 senses 를 분리**한다. 상황에 따라 뜻이 갈리면 반드시 별도 sense. 초급 기본 동사 2~4개, 중급 2~3개, 고급·비즈니스 1~3개. 뜻이 하나뿐인 단어는 1개로 둔다(억지로 늘리지 말 것).
2. `context` 는 한국어 상황 라벨 하나: "일상 대화", "가족/집", "학교/학습", "음식/식당", "쇼핑", "여행/교통", "건강/병원", "감정/관계", "직장/회의", "이메일/문서", "협상/영업", "재무/회계", "마케팅", "프로젝트/IT", "뉴스/시사", "정치/사회", "학술/글쓰기", "문학/묘사", "스포츠/취미", "기술/과학", "법률"
3. `pos`: n. / v. / adj. / adv. / prep. / conj. / phr. v. / idiom / colloc. 등 약어. `meaningKo` 는 사전식으로 간결하게("운영하다, 경영하다"). `meaningEn` 은 영영사전식 한 문장.
4. `examples`: sense 당 **2개**(고급·비즈니스 2~3개). **예문에 표제어 또는 변화형이 반드시 들어가야 한다**(검증기가 첫 단어 어간과 forms 로 확인). 불규칙 과거형(went, took)을 예문에 쓰려면 `forms` 에 넣어야 통과한다. ko 는 직역이 아닌 자연스러운 번역.
5. `note`: 뉘앙스·콜로케이션·한국인이 자주 하는 실수. 있을 때만.
6. `ipa`: 미국식, 슬래시 포함(/rʌn/). 구동사·관용구는 생략. `forms`: 불규칙 변화형만.
7. `register`: 격식 차이가 중요할 때만(neutral 은 생략). `tags`: 영문 소문자 주제 태그 1~3개.
8. `related`: 함께 익히면 좋은 표현 0~4개(표제어 문자열) — 혼동어(affect/effect), 짝 표현(borrow/lend), 자주 같이 쓰는 구동사. 없으면 생략.
9. id: `${레벨약자}-${타입약자}-${slug}` (word=w, phrasal=p, idiom=i, collocation=c; slug 는 소문자+하이픈, 아포스트로피 제거). 예: b-w-run, i-p-put-off, z-c-meet-a-deadline
10. `level` 과 `type` 은 배치 파일에 적힌 레벨·유형과 일치해야 한다.

## 작성 방법
- 배치 40개를 한 번에 쓰려 하지 말고 8~10개씩 node 스크립트나 heredoc 으로 append 하며 쓴다. 중간중간 `pnpm validate:part` 로 확인한다.
- JSON 문자열 안의 따옴표·백슬래시 이스케이프에 주의. heredoc 은 `<<'EOF'`(작은따옴표) 로.
